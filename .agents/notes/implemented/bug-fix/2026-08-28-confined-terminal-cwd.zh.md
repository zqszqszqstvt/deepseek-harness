# Agent Note: 受限终端工作目录

Status: implemented

[English](2026-08-28-confined-terminal-cwd.md) | 中文

## Problem

`terminal_open` 把 `cwd` 公开为初始工作目录，但面向模型的消费方会在 `read-only` 与 `workspace-write` 下把所有调用方值替换为工作区根目录。因此，合法的工作区子目录与省略参数产生相同结果。若直接删除替换而不增加其他检查，本地受限进程就可能继承挂载策略之外的宿主目录，从而在恢复参数语义的同时重新引入逃逸风险。

## Decision

面向模型的 `tool-terminal` 消费方会把 `cwd` 原样转发给所选终端后端，并且不依赖沙箱策略。这样可替换后端各自负责自己的路径域，而不会把宿主文件系统规则施加到所有后端类型。

本地 `terminal-bash` 后端会在创建进程前立即解析会话策略。在 `read-only` 或 `workspace-write` 下，省略 cwd 会选择规范化的工作区根目录，相对 cwd 基于该根目录解析；只有规范路径等于该根目录或位于其下时，显式 cwd 才会被接受。工作区外绝对路径、父目录遍历逃逸和符号链接逃逸都会在终端分配前被拒绝。在 `danger-full-access` 下，显式 cwd 保持不变，省略值继续以策略根目录为默认值。

## Verification

提供方测试覆盖相对与绝对工作区子目录、省略时的默认值、两种受限模式、工作区外路径、规范化符号链接逃逸，以及不变的 `danger-full-access` 行为。面向模型的消费方测试固定向可替换后端原样转发的行为。真实 Loader 组合会在工作区子目录中打开 shell，并从运行中的 PTY 观察该目录。

## Alternatives considered

**继续把每个受限 cwd 替换为工作区根目录。** 否决，因为这会让已公开参数对合法输入失效，并阻止调用方在其选定的项目子目录中打开交互式进程。

**在 `tool-terminal` 中校验 cwd。** 否决，因为该工具可以选择非本地的可替换后端，而这些后端的目录命名空间并不是宿主文件系统。本地后端同时拥有宿主进程创建和继承目录风险，应由它执行检查。

**依赖进程限制撤销继承的工作区外 cwd。** 否决，因为基于挂载的限制无法可靠移除进程已经继承的目录句柄。后端必须在分配前拒绝该 cwd。

## Consequences

受限本地终端可以从任意既有工作区目录启动，同时不会削弱工作区隔离。非法的受限 cwd 会直接失败，而不是被静默改成其他目录。`terminal-bash` 之外的后端实现会收到原始 cwd 请求，并继续负责其自身执行环境中的路径策略。
