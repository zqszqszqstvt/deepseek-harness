# Agent Note: Server 主机边界

Status: implemented

[English](2026-08-27-server-host-boundary.md) | 中文

## Problem

多用户 Server 是面向已鉴权平台后端的 HTTP 适配器，但命令帮助没有说明这一部署前提。能够直接访问 Server 的客户端可以任意指定 URL `userId`，进而选中其他租户的确定性工作区和会话。`0.0.0.0` 的示例也没有注明可信网络条件。

Server 自身的请求失败还会原样返回异常或 ApiProxy 错误消息。文件系统和持久化失败可能包含主机绝对路径，因此原样中继这些响应的平台会向终端租户暴露主机布局。ApiProxy mux 的终止错误在 SSE（Server-Sent Events）上存在相同问题。

复制 Server 数据目录时，每个会话头仍保留原工作区的绝对 `cwd`。副本在新的绝对 `--data-dir` 启动后，会用不同 cwd 请求相同的确定性 session ID，导致每个回访用户永久收到 `session-conflict`，即使日志和工作区确实属于该用户。

## Decision

`dsh server` 被明确规定为不提供认证层的内部服务。帮助文本要求仅绑定回环地址或部署在可信后端网络中。后端负责认证调用方、从该主体派生 URL `userId`，并且不得接受调用方可控的 `userId`。监听全部接口的示例会明确注明可信网络要求。

本地校验的请求错误保留具体且安全的消息。异常和失败的 ApiProxy 结果统一返回 HTTP `500` 与 `server request failed`；mux 终止失败发送 `event stream failed` 且详情为空。Server 日志记录原始异常或结果，包括主机诊断信息。普通会话事件属于租户自己的 agent（智能体）对话记录，本适配器不改写这些事件。

采用确定性用户会话之前，Server 会检查 JSONL 产物。如果其中的 cwd 与当前工作区不同，只有旧 cwd 以 `users/<完整 SHA-256 用户键>/workspace` 结尾时才允许自动迁移。其他占用相同 ID 的会话仍会被拒绝。JSONL 后端会重写冷会话头、在已配置的持久化根目录内移动会话目录、使协调器中的冷状态失效，同时保留 ID 和事件日志。会话头替换先于目录移动，因此进程在两次提交之间中断后，重试可以完成迁移。同一用户的并发首次请求共享同一个初始化操作。

## Verification

Server HTTP 测试证明：抛出的异常和失败的 ApiProxy 结果会在日志中保留主机路径，但响应只包含公开文案。SSE 测试证明：上游终止消息会被记录且不会出现在发出的帧中。真实 Server 路由测试会迁移旧布局的用户会话，并拒绝不相关 cwd 下占用相同 ID 的会话。JSONL 测试覆盖明文和默认 Zstandard 迁移、事件与身份保留、幂等性和活动会话拒绝；Win32 测试固定替换标志。项目引用 TypeScript 构建覆盖两个已修改包。

## Alternatives considered

**要求运维人员在移动 `dataDir` 时编辑会话日志。** 不采用，因为不可变 cwd 是实现细节；复制完整且自包含的 Server 数据根目录后，不应要求逐用户修复才能继续使用。

**从 `dataDir` 派生新的 session ID。** 不采用，因为每次路径变化都会静默放弃用户的对话历史并创建新身份。

**不检查旧 cwd，迁移所有同 ID 会话。** 不采用，因为与非 Server 会话发生碰撞时，不得让该会话因此获得租户工作区访问权。完整 SHA 目录证明把迁移限制在由同一 Server 用户布局创建的产物上。

**在该 bundle 内增加认证。** 不采用，因为凭据验证和主体映射属于集成平台。Server 明确并保持这一职责划分，而不是引入第二套不兼容的身份系统。

## Consequences

平台租户不会通过 Server 自身的 HTTP 或 SSE 终止错误收到 Server 基础设施路径，运维人员仍能获得完整诊断。Server 只有位于负责 `userId` 的可信鉴权后端之后时，才能安全地暴露到回环地址之外。移动完整 `dataDir` 会保留回访用户的确定性会话和历史。将用户工作区有意改为无关布局、迁移活动会话或与非 Server 会话发生碰撞时仍会失败，并需要运维人员介入。
